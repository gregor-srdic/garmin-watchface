# Spec: battery next to weather, touch-to-open arcs

Intent: `intent.md` (same folder). User decisions from 2026-11-06 are recorded there.

## Areas of concern (up front)

- **"Tap" is really touch-and-hold (conflicts with the intent).** In SDK 9.3.0,
  the only touch event a watch face receives in normal use is
  `WatchFaceDelegate.onPress`, which the docs describe as "called when user does a
  touch and hold" (API 4.2.0, all 11 manifest devices). `onTap` exists from API 5.1.0,
  but it's documented as "only available in WatchFace config mode". So the feature
  is **touch-and-hold an arc to open it**. The system uses a short tap on the face
  itself, and we can't intercept it. This is how Garmin's own faces behave
  (hold a complication to open it). **Needs user acknowledgement before build.**
- **Long-press conflicts with the system menu.** On some devices, holding the
  watch face opens the system's watch-face menu. When `onPress` returns `true`, the
  system's action is suppressed. The plan: return `true` only when we actually
  launch something. Holding the time, date or weather row, or holding an arc whose
  metric can't be launched, returns `false`, so the system's default still
  happens. Because the hit area covers the whole quadrant, the system menu can be
  reached only from the centre block. This is the trade-off of answer 5.
- **No launch target (answer 4).** The "do nothing" check is
  `Complications.getComplication(id)` (via `safeGetComplication`). If that returns
  null, or `exitTo` throws, `onPress` returns `false`. The SDK doesn't say
  whether every device has a native app for calories. This can only be checked on
  a device, and the simulator may not launch anything.
- **Glyph availability.** The system fonts don't reliably include ⚡, so the
  battery and charging icons are PNGs generated by a tool script, the same way the
  weather icons are made. The ` · ` separator is already used in the date row, so
  it's known to render.
- **Row width.** The row grows to roughly `⛅ 18° · ▭ 78%` ≈ 185 px at 454 px. The space
  between the bottom arcs at that height is ≈ 250 px, and the bottom arc labels sit
  higher up (just under the time), so they don't overlap. This gets checked
  visually in the simulator.
- **Battery reading cost.** `System.getSystemStats()` is a cheap call, and it's
  read once per `onUpdate` in active mode only. No extra wake-ups.
- **Red reuses the heart-rate accent** (`0xff4d4d`), so no new color enters the
  palette. *My call.*

## Requirements

### Battery
- B1 The row under the time reads, left to right: weather icon, temperature,
  separator ` · `, battery icon, battery percentage. Example: `⛅ 18° · ▭ 78%`.
- B2 When temperature is unavailable (today the whole row is hidden), the row shows
  only `▭ 78%`, centred. If only the weather icon is missing, the existing rule
  applies: the temperature shows without an icon.
- B3 Percentage = `Math.round(stats.battery)`, clamped to 0–100, with `%` appended.
- B4 Low = percentage ≤ 15 **and not charging**. When low, the battery icon and
  percentage are red `0xff4d4d`. Otherwise the percentage is `COLOR_TEXT`
  (`0xcccccc`), the same as the temperature.
- B5 Charging (`stats.charging == true`): the battery icon is replaced by a ⚡ icon,
  and the percentage stays `COLOR_TEXT`. Being charged overrides being low. *My call:
  a red figure while it's charging would read as an alarm.*
- B6 Separator ` · ` is `COLOR_TEXT`.
- B7 Always-on (low power) mode doesn't change.

### Touch-and-hold to open
- T1 Holding a point on the screen maps to an arc slot by quadrant around the
  screen centre: top-right → 0 (stress), bottom-right → 1 (calories),
  bottom-left → 2 (body battery), top-left → 3 (heart rate). This matches the
  existing slot order.
- T2 These excluded rectangles map to no slot: the time block
  (its drawn width × `timeRenderH`), the date row, and the weather/battery row
  (each one's drawn text width × `rowH`). The arc icon/value labels are **not**
  excluded. They belong to their quadrant.
- T3 On a hit, if that slot's complication exists, call
  `Complications.exitTo(id)` and return `true`. In every other case (miss,
  low-power mode, `Complications` unsupported, complication missing, `exitTo`
  throws), return `false` and change nothing.
- T4 Buttons and non-touch behaviour don't change. No `onTap` handling.

## Design

- **`ArchesLogic` (pure, unit-tested)**
  - `batteryPercent(battery as Float) as Number`: round and clamp.
  - `batteryText(pct as Number) as String`: `"78%"`.
  - `isBatteryLow(pct as Number, charging as Boolean) as Boolean`: B4.
  - `slotAt(x, y, cx, cy, excluded as Array<Array<Number>>) as Number?`:
    T1/T2. Each excluded rect is `[left, top, right, bottom]`. Points on an axis
    resolve deterministically (`dx >= 0` → right, `dy < 0` → top).
- **`ArchesWatchFaceView`**
  - `drawWeather()` becomes `drawInfoRow()`. It builds the parts list
    (icon?, temp?, sep, battery icon, pct), measures it, centres it and draws it.
    Battery/charging bitmaps are loaded once and cached, like the arc icons.
  - It records the drawn rectangles of the time block, date row and info row each
    active frame (`_hitExclusions`), so hit-testing matches what's on screen.
  - New public `slotAtPoint(x, y)` and `compIdForSlot(i)`.
- **`ArchesWatchFaceDelegate`** (new, `source/ArchesWatchFaceDelegate.mc`):
  extends `WatchUi.WatchFaceDelegate`, holds the view, and implements `onPress` per
  T3 (wrapped in `try/catch`).
- **`ArchesWatchFaceApp.getInitialView()`** returns `[view, delegate]`.
- **Assets:** `tools/gen_battery_icons.py` → `battery.png` (gray `#cccccc`),
  `battery_low.png` (red `#ff4d4d`), `battery_charging.png` (⚡, pale yellow
  `#ecdea0`, same as the moon). All are 32×32 flat icons on a transparent
  background, matching the weather icons, and registered in `drawables.xml` as
  `IconBattery`, `IconBatteryLow`, `IconBatteryCharging`.
- **README:** the feature list, architecture table, layout notes and a
  "touch-and-hold an arc" line.

## Verification
- Unit tests (`test/ArchesLogicTest.mc`) for `batteryPercent` (78.4→78, 78.5→79,
  −1→0, 100.6→100), `isBatteryLow` (15/false→true, 16→false, 10/charging→false),
  `batteryText`, and `slotAt` (one point per quadrant, an excluded point → null, a
  label position → its slot, axis tie-breaks).
- Build for all 11 products without new warnings.
- Simulator (fr965, plus venu3 as a second font set), with screenshots at
  battery 78%, 10%, and charging, plus weather on and off. Check the row clears the
  arcs.
- Simulator touch-and-hold on each quadrant and on the time: no crash, and the
  return value gets logged. Whether apps actually launch can only be confirmed on a
  device (the user's watch).

## Out of scope
Configurable arcs (next change), status icons, always-on battery display.
